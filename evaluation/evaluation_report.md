# Evaluation report

## Scope and measured results

Evaluated against all 32 public sample answers in `dataset/sample_output.csv`.
The prediction code never reads that answer file. No organizer-only files were accessed.
Public samples informed debugging, so these results are development-set results, not an unbiased held-out estimate.
Accuracy on the 518 submission requests is **unknown** because their reference answers are not participant-facing.

| Metric | Result |
| --- | ---: |
| Case-level deletion-status accuracy | 23/32 (71.88%) |
| Exact step precision | 142/163 (87.12%) |
| Exact step recall | 142/193 (73.58%) |
| Step F1 | 79.78% |
| Field-level accuracy | 1044/1386 (75.32%) |
| Exact sequence accuracy | 8/32 (25.00%) |
| Exact full output row accuracy | 8/32 (25.00%) |
| Participant-created regression tests | 13/13 passed |

Step matching compares phase, system, resource, operation, state, and evidence ID as a multiset, excluding step number.
Field accuracy aligns by (phase, system, resource); all seven fields are scored, and a missing or extra step contributes seven errors.
Sequence accuracy compares the entire ordered JSON array, including numbering and evidence references.
Full row accuracy requires both status and exact sequence. These local definitions are explicit; the hidden grader may use different aggregation.

## Failures found and improvements made

1. Initial intent inference rejected deletion-audit wording and removal of historical records. Added explicit positive language recognition after refusal guards; the local classifier remains available for less explicit wording.
2. Screenshot extraction initially associated all visible table customers with the selected resource. Scoped primary-resource identity to the explicit catalog link and its availability timestamp.
3. Pipe-delimited logs initially used the wrong column-count check. Corrected it and added cross-dialect regression coverage.
4. A PDF catalog alias based only on a stable user reference matched an unrelated multi-subject register. Restricted document aliases to explicit export references; user co-occurrence alone is not resource ownership.
5. Added dual time checks (file availability and embedded observation time), exact normalized identity matching, replica conflict handling, and preservation of stable tombstone references.

## Remaining limitations — this is a baseline, not a fully solved submission

The public-sample exact sequence score is 25.00%; the output should not be represented as fully accurate.
Many absence/anonymization readbacks contain only a resource ID, with no subject identifier or explicit provenance connecting that resource to a person.
The pipeline intentionally does not assign these records using numeric case/user/resource suffixes, fixed timing offsets, event order, or sample labels.
For example, the public answer for case_01 requires account_001, while the visible activity identifies that target without an email/user link; the SQL snapshot proves absence only after the target is known.
Some sample answers cite readback files that do not contain the named retained resource (for example audit_record_4128 in evidence_92). These gaps are not repaired with invented observations.
As a result, some known compliant cases become INCOMPLETE with diagnostics, and some sequences omit unlinked records.
The fixed output schema has no UNKNOWN status, so missing-proof cases are conservatively serialized as INCOMPLETE; this is a documented limitation, not a proven policy violation.

Other limits: OCR may miss or misread text; screenshot interpretation supports the supplied view types rather than arbitrary applications.
The local intent model and explicit language guards are not a general multilingual LLM, and complex mixed-scope consent needs additional coverage.
Policy handling uses the supplied categories and conditions represented in the observed records; missing or expired retention/hold metadata is not inferred as permission to delete.
Resource ordering follows the specified phase/operation/system/resource order. Explicit flow and restore gates precede record changes; arbitrary record-to-record dependency graphs are not inferred.
No real deletion, external mutation, or hosted inference is performed.
